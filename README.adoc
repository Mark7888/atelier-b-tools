== List of tools

=== initABWS-2404.sh

This bash script makes an Atelier B workspace directory form an empty directory. It will create the _bdb_ database folder, and a config file named _AtelierB_ for this workspace. 

==== Prerequisites

* Installed Atelier B 24.04.2.

* The directory is empty

==== Usage

Put this file in a directory that is in the $PATH environment variable, or create a simbolic link here.

You can run this script from an empty directory. If the directory is not empty the script will exit immediately. The script will ask the path of the installed Atelier B.

=== startBB-2404.sh

This bash script starts a bbatch console. You can use this script for Atelier B 204.04.2.

==== Prerequisites

* Installed Atelier B 24.04.2.

* The workspace directory contains its config file (AtelierB).

==== Usage

Put this file in a directory that is in the $PATH environment variable, or create a simbolic link here.

You can run this script form an Atelier B workspace directory that contains the project directories, the _bdb_ database directory and the workspce config file (AtelierB). If the workspace directory doesn't contain a file named _AtelierB_, the script will exit immediately.

=== syncABWS-2404.sh

This bash script syncronize the workspace directory into the workspace database. Add, remove and sync projects with the workspace database. If you add a folder to the workspace directory, the script will create a project with folders name. If you delete the whole directories of a project, it will be removed from the worksapce project as well. Moreover, the components of the projects will be synchronized as well.

==== Prerequisites

* Installed Atelier B 24.04.2.

* The workspace directory contains its config file (AtelierB).

* The parent directory of startBB-2404.sh is on the PATH.

==== Usage

Put this file in a directory that is in the $PATH environment variable, or create a simbolic link here.

If you added a new projects or component file or deleted you should run this script in order to the projects in the Atelier B presentation will be godd and synchronized with the file system.

== Windows batch files

The corresponding Windows scripts are `initABWS-2404.bat`, `startBB-2404.bat`, and `syncABWS-2404.bat`. Run them from a Command Prompt in the workspace directory. Put the batch files together in a directory on `PATH`, or invoke them by their full paths. The sync script also finds `startBB-2404.bat` beside itself.

Set `ATELIERB_PATH` to the Atelier B 24.04.2 installation directory before starting or synchronizing a workspace, for example:

[source,bat]
----
set "ATELIERB_PATH=C:\Program Files\Atelier B 24.04.2"
startBB-2404.bat
syncABWS-2404.bat
----

Run `initABWS-2404.bat` from an empty directory. It prompts for the installation directory and creates `bdb`, `Archives`, and the `AtelierB` configuration file. Its prompt does not set `ATELIERB_PATH` in the parent Command Prompt; set that variable separately before using the other two batch files.

== macOS scripts

The macOS versions are `initABWS-2404-macos.sh`, `startBB-2404-macos.sh`, and `syncABWS-2404-macos.sh`. They work the same way as the Linux scripts and run with the bash and command-line tools that ship with macOS. Put them together in a directory on `PATH` (the sync script also finds `startBB-2404-macos.sh` beside itself).

Differences from the Linux scripts:

* The Atelier B installation is found automatically in `/Applications`, `~/Applications`, or `/opt/atelierb*`. Both a plain installation folder and a `.app` bundle work. If it is somewhere else, set `ATELIERB_PATH`:
+
[source,sh]
----
export ATELIERB_PATH="/Applications/AtelierB-free-24.04.2.app"
startBB-2404-macos.sh
syncABWS-2404-macos.sh
----
* `initABWS-2404-macos.sh` offers the detected installation as the default answer, and ignores a `.DS_Store` file when checking that the directory is empty.
* `startBB-2404-macos.sh` sets `DYLD_LIBRARY_PATH` (the macOS equivalent of `LD_LIBRARY_PATH`).

If macOS blocks `bbatch` because it was downloaded from the internet, allow it in *System Settings > Privacy & Security*, or remove the quarantine flag with `xattr -dr com.apple.quarantine <installation path>`.
